If you want a feel for the tool first, load the example schedule and change things freely. When you
are ready for the real thing, add your roster and make one slot for each match or scrim.

## Board or Grid?

Both edit the same schedule, so switch whenever you like.

| View      | Best for                                                                                      |
| --------- | --------------------------------------------------------------------------------------------- |
| **Board** | Laying matches out visually, dragging players around, building lineups by hand, and pairing players. |
| **Grid**  | Filling in availability fast across a big roster, with the mouse or the keyboard.              |

### Working on the Board

The Board has a player **Pool** and one box for each match time. Drag players from the Pool into a
match, or use a player's menu to move or copy them. You can move the board around, zoom in and out,
rearrange the boxes, and pin the Pool to a corner so it stays put while everything else moves.

Double-click an empty spot to add a match time there. The buttons in the bottom-right corner zoom
out, zoom in, reset the zoom, and fit the whole schedule on screen.

<Tip>
	**Board help** in the header lists every way to move, select, and place players with a mouse,
	keyboard, or touchscreen. It also shows up once the first time you open a board.
</Tip>

![The Battles Scheduler Board before simulation, showing a player pool and ten match-time containers](../../images/scheduler/scheduler-board.png)

### Filling in the Grid

The Grid puts players down the side and match times across the top. Click or drag across the cells
to set availability. Arrow keys move around, Space changes the cell you are on, and Shift with an
arrow key paints several cells at once.

Each player row has actions to set, clear, or flip that whole row, and each match column has the
same for the column, plus its pairing rules.

![The Battles Scheduler Grid showing availability for 26 players across ten match times](../../images/scheduler/scheduler-grid.png)

## Set up each match time

Every match needs a date and a start time. You can also give it a label, such as the opponent or the
round, and change how many players it needs.

Times start out in your own time zone. If a match was announced in another region, set that match to
the other region's zone and type the time exactly as it was given to you. Battles Scheduler shows
which zone it is in wherever that time appears.

The **Slot actions** menu also duplicates a match, copies players in from another match, assigns
duties, clears its players, or deletes it.

## Mark who can play

Availability is per match, so a player can be free on Saturday and busy on Sunday.

| Mark             | Use it when                                                                                     |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| **Not in this time slot** | The player is not in the running for this match at all.                                 |
| **Can play**     | The player is free.                                                                             |
| **Maybe**        | The player could step in if needed. These are held back until the alternative is an empty seat.  |
| **Must play**    | The player should start, unless your other rules make that impossible.                          |
| **Cannot play**  | The player is ruled out of this match.                                                          |

Tick **Can host** or **Can call** on the players who can take those jobs, and Battles Scheduler will
use them when it assigns Host and IGL.

## Duties and pairings

Open **Duties...** on a match to leave Host and IGL on **Auto** or name someone yourself. Naming
someone does not force them into the lineup - if the duty cannot be filled, you get a warning.

Pairings are set per match too:

- **Together** asks for both players to start, or both to sit.
- **Apart** asks for those two not to start the same match.

These are preferences, not rules. Availability, holding back Maybe players, filling seats, and
fairness all come first. Anything that could not be honored shows up in the fairness summary.
